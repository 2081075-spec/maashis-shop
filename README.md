# MAASHI's SHOP — 公開・更新ガイド

このフォルダ一式をアップロードするだけで、完全無料でお店のページを公開できます。

## フォルダの中身

| ファイル | 役割 | 触る頻度 |
|---|---|---|
| `index.html` | お客様が見るお店のページ本体（商品595件を内蔵） | ほぼ触らない（新商品追加時のみ） |
| `stock.json` | 価格・在庫・非表示だけを上書きする小さなファイル | **1日2回、ここだけ更新** |
| `admin.html` / `admin.js` | 在庫・価格を編集して `stock.json` を作るための管理画面（非公開ツール） | 更新のたびに使う |

`index.html` は元々「stock.json があれば、その内容で価格・在庫を上書きする」仕組みが最初から組み込まれていました。
これを使うことで、228KBある本体ファイルを毎回触らずに、数KBの `stock.json` だけ差し替えれば更新が完了します。

## 1. 公開する（無料 / GitHub Pages）

1. https://github.com/join でGitHubアカウントを作成（無料）
2. ログイン後、右上の「+」→「New repository」で新規リポジトリを作成
   - Repository name: 例 `maashis-shop`
   - Public を選択
   - 「Create repository」
3. 作成後の画面で「uploading an existing file」というリンクをクリックし、このフォルダの中身
   （`index.html`, `stock.json`, `admin.html`, `admin.js`）をまとめてドラッグ&ドロップ →「Commit changes」
4. リポジトリの「Settings」タブ →左メニュー「Pages」
   - 「Branch」を `main` / `/(root)` に設定 →「Save」
5. 1〜2分待つと、ページ上部に公開URLが表示されます
   `https://（あなたのユーザー名）.github.io/maashis-shop/`
   これがお客様に共有するURLです。完全無料・維持費もかかりません。

管理画面は `https://（あなたのユーザー名）.github.io/maashis-shop/admin.html` になります。
※検索エンジンには載らずリンクも張っていませんが、URLを知っていれば誰でも「閲覧」はできます。
　ただし実際に在庫を書き換えて公開まで反映できるのはGitHubにログインできる人だけなので、
　URLを人に教えない限り実質問題ありません。

## 2. 1日2回の在庫更新（本番運用はここだけ）

1. `admin.html` をブラウザで開く（GitHub Pages公開後のURLで開くのが確実）
2. 検索欄や絞り込み（種別・シリーズ・在庫少のみ表示 など）で対象商品を探す
3. 価格・在庫の数字を書き換える／売り切れなら「非表示」にチェック
4. 画面上部の「⬇ stock.jsonをダウンロード」ボタンを押す
   → `stock.json` という名前でダウンロードされます
5. GitHubのリポジトリ画面を開き、既存の `stock.json` に上書きアップロード
   （「Add file」→「Upload files」でダウンロードしたファイルをドラッグ＆ドロップ →「Commit changes」）
6. 1〜2分でお店のページ（`index.html`）の価格・在庫・最終更新日時が自動的に反映されます

これを1日2回（朝・夜など）繰り返すだけです。コードやJSONを直接いじる必要はありません。

---

## 3. 新商品の追加・削除について

商品そのもののリスト（名前・画像・シリーズなど）は `index.html` の中に直接埋め込まれています。
これは日々の在庫更新とは別作業になるため、新商品を追加したい場合は元の書き出し元（カタログの
出力元システム）から新しい `index.html` を作り直して差し替える運用を想定しています。
（在庫・価格の調整だけであれば `stock.json` の更新のみで完結します。）

---

## 補足：他の無料ホスティングを使いたい場合

GitHub Pages 以外にも Cloudflare Pages・Netlify なども無料で使えます。どれも
「フォルダごとアップロード」→「公開URLが発行される」という流れは共通です。
GitHub Pagesは設定項目が少なく、ファイルの上書きもブラウザだけで完結するため、
非エンジニアの方が1日2回更新する運用には最も手間が少ない選択肢としておすすめです。
